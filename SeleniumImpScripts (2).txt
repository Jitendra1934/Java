What are the Important classes and interfaces in Selenium


-> WebDriver Interface:

	-> the main interface of selenium that provides the methods to interact with the browser 

	-> methods like get(), findElement(), findElements(), quit()

-> WebElement Interface:

	-> Represent the HTML element on the web page 

	-> Provides methods like click(), sendKeys(), getText(), getAttribute() etc.

-> By Class:

	-> Methods to specify the how to locate the HTML elements on the web page 

	-> Methods like id(), name(), className(), cssSelector(), xpath() etc

-> Actions Class:

	-> Provides the methods for Mouse Movements, KeyBoard Interactions and Drag and drop operations.

	-> moveToElements() ---------- Mouse Actions 
	-> KeyDown() and KeyUp() ------------- KeyBoard Interactions 
	-> DragAndDrop() ------------------- For files drag ang drop 

-> Alert Interface:

	-> Represents a JavaScript alert box on a web page.

	-> Methods like accept(), dismiss(), getText() etc.

-> Select Class:

	-> Provides the methods for interacting Dropdowns and Multiple checkboxes 

	-> Methods like selectByIndex(), selectByValue(), deselectAll(), selectByVisibleText() etc.

-> WebDriverWait Class:

	-> Provides the methods for waiting for certain conditions occure on the web page 

	-> Methods like until(), withTimeout() etc.


-> ExpectedConditions Class:

	-> Provides pre-defined conditions for use with WebDriverWait.

	-> Methods like visibilityOf(), invisibilityOf(), elementToBeClickable() etc

These are the building blocks of your feature files. They are not Java annotations.

Feature: Defines the overall functionality or area under test.

Example: Feature: User Login Functionality

Scenario: Describes a single, specific example of how the feature works.

Example: Scenario: Successful Login with Valid Credentials

Background: Used to define a set of steps that are common to all scenarios within a feature. It runs before each scenario but after any @Before hooks.

Example:

Gherkin

Background:
  Given User is on the homepage
Given: Defines the initial context or pre-conditions.

Example: Given I am on the login page

When: Describes the action or event.

Example: When I enter "username" and "password"

Then: Describes the expected outcome or post-condition.

Example: Then I should be redirected to the dashboard

And: Used to combine multiple Given, When, or Then steps for better readability without repeating the keyword.

Example: Given I am on the login page And I have an active internet connection

But: Similar to And, but usually used to express a contrasting condition.

Example: Given I am on the login page But my account is locked

Scenario Outline: (Also known as Scenario Template) Allows you to run the same scenario multiple times with different sets of data. It uses placeholders in the steps.

Example:

Gherkin

Scenario Outline: Login with various credentials
  Given I am on the login page
  When I enter <username> and <password>
  Then I should see <message>

  Examples:
    | username | password | message              |
    | user1    | pass1    | "Welcome, user1!"    |
    | user2    | pass2    | "Invalid Password!"  |

In summary:

Feature, Scenario, Background, Scenario Outline, Examples, Given, When, Then, And, But (and their variations) are Gherkin keywords used to write your test scenarios in plain language in .feature files.

The @Given, @When, @Then, @And, @But, @Before, @After, @BeforeStep, @AfterStep, @ParameterType, @DataTableType are Java annotations that connect these Gherkin steps and manage test execution flow in your Java code.

So, while your list includes 11 terms crucial to Cucumber, only a subset of them are true Java Annotations in the programming sense. The others are Gherkin syntax elements.
